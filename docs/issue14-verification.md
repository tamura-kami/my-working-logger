# Issue #14 検証記録

## 自動検証

`npm run check` で型検査、Vitest（ローカル時計・DOM・Miniflare/D1）、Safari 15を対象にした本番ビルドを実行する。

検証対象:
- 通常タイマーの進行中・一時停止中の保存と復元、休止時間を含む実績の整合性。
- ポモドーロの自動進行、復帰時の満了停止、JS停止・バックグラウンド復帰、次フェーズの明示開始。
- 長休憩直前の確定、閉じていた最後の集中の予定時刻による確定、途中終了とスキップ。
- 開始・一時停止・再開で通信しないこと、保存応答が新しい実行状態を消さないこと。
- 保存失敗後の同一ID再送、同時再送、バッチ失敗時のロールバック、編集・削除後の再送。
- 保存破損・未知のバージョン・書込み失敗時に既存データを失わないこと。
- マイグレーションが既存の確定実績を維持し、旧状態API・テーブルを撤去すること。

## Safari 15 / iPadOS 15

実機未検証。この実行環境には利用可能なブラウザも接続されていないため、実ブラウザの表示・タッチ操作確認も未実施。Safari 15向けビルドとDOMテストは実機確認を代替しない。

新実装はDate.now、localStorage、JSON、fetch、既存のAudioContextを使う。UUIDは既存のcrypto.getRandomValues実装を使い、crypto.randomUUID、Web Locks、Service Worker等を要求しない。

実機で以下を確認する:
1. 通常タイマー開始→リロード／ブラウザ終了・再表示→経過時間が増えている。一時停止で同じ操作を行うと値が維持される。
2. 集中・短休憩・長休憩を1分にして、表示中に自動移行し、回数が集中中1/Nから始まり、長休憩後1/Nへ戻る。
3. 集中途中のリロードは残り時間を維持。満了後の再表示は当該フェーズ00:00で停止し、明示操作で次へ進む。
4. バックグラウンド／端末スリープから満了後に戻ると同様に停止。短休憩・長休憩でも確認する。
5. 一時停止して再表示すると残り時間・フェーズ・回数が維持される。
6. 最後の集中満了前に閉じ、満了後に開くと予定時刻までの実績を1件保存し、長休憩は未開始。
7. オフラインで途中終了し、未保存実績が残る。再表示／オンライン復帰／再送で1件だけ保存する。
8. 画面の残り時間・直下の回数・下部ボタンが縦横表示で重ならず、音の有効化、停止・再開・終了確認がタッチ操作できる。
